    第 1 行指出，PostgreSQL 的连接器 ADO.NET 无法删除现有数据库。 这与 Oracle 的情况完全相同。因此，我们需要使用工具 [EMS Manager for PostgreSQL] 手动构建数据库 [RDVMEDECINS-EF]。本文不详述所有步骤，仅介绍最重要的部分。

    PostgreSQL 数据库结构如下：

    表

    • 在 [1] 中，ID 是类型为 serial 的主键。该类型 PostgreSQL 是由 SGBD 自动生成的整数。

    各个表拥有与前面的示例中相同的表的主键和外键。外键具有属性 ON DELETE CASCADE。

    序列

    与 Oracle 类似，我们在此创建了序列。它们是连续数字的生成器。共有 5 个：[1]。

    • 在 [2] 中，我们可以看到序列 [CLIENTS_ID_SEQ] 的属性。它生成从 1 开始、以 1 为增量、直至非常大值的连续数字。

    所有序列均基于相同的模式构建。

    • [CLIENTS_ID_seq] 将用于生成表 [CLIENTS] 的主键；
    • [MEDECINS_ID_seq] 将用于生成表 [MEDECINS] 的主键；
    • [CRENEAUX_ID_seq] 将用于生成表 [CRENEAUX] 的主键；
    • [RVS_ID_seq] 将用于生成表 [RVS] 的主键；
    • [sequence_versions] 将用于生成所有表中 [VERSIONING] 列的值。

    触发器

    触发器是由 SGBD 在表中发生某项事件（插入、修改、删除）之前或之后执行的存储过程。我们有 4 个 [1]：

    让我们查看触发器 [CLIENTS_tr] 的代码 DDL，该触发器为表 [CLIENTS] 的列 [VERSIONING] 提供数据：

    1
2
3
4
    CREATE TRIGGER "CLIENTS_tr"
  BEFORE INSERT OR UPDATE 
  ON public."CLIENTS" FOR EACH ROW 
EXECUTE PROCEDURE public.trigger_versions();
    • 第 1-3 行：在表 [CLIENTS] 上执行每次 INSERT 或 UPDATE 操作之前；
    • 第 4 行：执行过程 [public.trigger_versions()]。

    过程 [public.trigger_versions()] 如下：

    1
2
3
4
    BEGIN
NEW."VERSIONING":=nextval('sequence_versions');
return NEW;
END
    • 第2行：NEW 表示即将插入或修改的行。NEW。“VERSIONING”是该行的[VERSIONING]列。 为其分配数字生成器的下一个值“sequence_versions”。 因此，每当在表 [CLIENTS] 上执行 INSERT / UPDATE 操作时，列 ["VERSIONING"] 就会发生变化。

    触发器 [MEDECINS_tr, CRENEAUX_tr, RVS_tr] 的工作原理与此类似。四个 ["VERSIONING"] 列的值均来自同一序列。

    用于生成数据库表的脚本 PostgreSQL 和 [RDVMEDECINS-EF] 已放置在文件夹 [RdvMedecins / databases / postgreSQL] 中。读者可加载并执行该脚本以创建表。

    完成上述操作后，即可运行项目中的各个程序。它们产生的结果与 SQL Server 相同，但 [ModifyDetachedEntities] 程序除外——该程序会因与在 Oracle 环境中相同的理由而崩溃。解决该问题的方法与之前相同。 只需将 [RdvMedecins-Oracle-01] 项目中的 [ModifyDetachedEntities] 程序复制到 [RdvMedecins-PostgreSQL-01] 项目中即可。
